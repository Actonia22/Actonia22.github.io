学习日记2 Web入门

本篇博客简要介绍了Web方向上常见的一些漏洞，进行一个初步的了解。

一、 信息泄露

定义：
源代码/配置文件/系统内部信息 被非法访问。

常见场景：

Git/SVN版本控制文件泄露：
程序员用Git/SVN管理代码时，会生成一个隐藏的.git目录（存代码修改历史）。如果部署网站时没删这个目录，攻击者就能通过访问 /项目名/.git/ 下载整个项目的源码（包括密码、漏洞）。

网站备份文件遗留：
网站管理员备份文件时，会生成.bak（备份副本）、.swp（临时文件）、.zip（压缩包）。同理，如果没有删除这些，攻击者可以获得敏感信息。

目录遍历：
网站服务器配置错误，允许通过URL“跳目录”访问不该访问的文件。
简单解释就是网站代码没有过滤 ../ 这种向上跳转目录的符号，攻击者可以用这个方法读取服务器上任意文件。
示例：?file=../../../../etc/passwd 最终读取到Linus系统根目录。
注：/etc/passwd 是Linux 系统的用户清单文件。

CTF典型示例：
扫描.git目录拿源码（运用工具扫描网站，下载 /.git/ 目录）

输入 ?file=../../../../etc/passwd 读系统核心文件

危害： 攻击者可分析源代码漏洞直接攻击网站，分析配置文件窃取用户数据，拿到系统内部信息精准攻击。

二、 命令执行漏洞（RCE）

原理剖析：
应用程序未对用户输入进行严格安全过滤,用户能通过输入控制服务器执行任意命令

毁灭性危害： 这是Web安全领域最严重的漏洞之一。攻击者利用RCE可获取与Web服务同等权限的服务器控制权，进而执行任意操作（如增删改查文件、反弹Shell、植入持久化后门），对系统安全造成毁灭性打击。

可能引发RCE的高危函数：

语言 危险函数
PHP system()、exec()、passthru()、eval()
Python os.system()、subprocess.run()
Java Runtime.getRuntime().exec()、ProcessBuilder
Node.js child_process.exec()、child_process.spawn()
  • system()：执行系统命令
  • exec()：执行命令并返回输出
  • passthru()：执行命令并输出原始结果
  • eval()：执行PHP代码
  • os.system()：执行系统命令
  • subprocess.run()：执行命令并获取结果，未过滤输入
  • Runtime.getRuntime().exec()：执行系统命令
  • ProcessBuilder：构建进程，未过滤输入
  • child_process.exec()：执行命令并回调结果
  • child_process.spawn()：启动新进程，未过滤输入

关键提醒：这些函数本身没问题，但未对用户输入做安全过滤（如escapeshellarg()）就会导致RCE！

经典Payload：
?ip=127.0.0.1;cat /flag (通过 ； 拼接命令，先执行IP，再执行cat /flag 即读取敏感文件)

ping -c 3 127.0.0.1 | whoami （通过 | 拼接命令， 与上文同样道理，whoami是用于获取当前用户权限）

注：构造payload有一些技巧，如命令拼接（用分号 ； 管道符 | 反引号` 等）
编码绕过（将命令伪装成乱码 方法有Base64编码，URL编码等 由于方法较为陌生 后面深入学习会再次介绍）
盲命令执行（攻击者无法直接看到命令输出的结果，可通过Ping探测，Curl传结果等方法侧面判断命令是否成功执行）

三，文件包含与文件上传

文件包含

本质：服务器加载用户指定的文件，但未对路径做安全检查，攻击者可以骗服务器加载任意文件。

类型：

本地文件包含（LFI）：只能包含服务器本地的文件（如/var/log/apache2/access.log）。

远程文件包含（RFI）：能包含外部URL的文件。

常见利用场景：

读取敏感文件：通过包含日志文件（如Apache：网页服务器软件 的access.log）、临时文件（如PHP：后端脚本解释器 的session文件）、配置文件（如/etc/passwd）获取信息。

例子：

?file=../../../../var/log/apache2/access.log（包含日志，里面有用户访问记录）。

注： - ?file=：表示我要包含的文件路径，?file=xxx会让服务器读取xxx文件并显示内容。

  • ../../../../：是路径跳转的意思

  • var/log/apache2/access.log：这是Linux系统中Apache服务器的访问日志文件，里面记录了所有访问该网站的用户信息

php://filter/convert.base64-encode/resource=secret.php（读取加密源码）。

注： - php://：这是PHP的伪协议，可进行特殊操作。

  • filter：用于处理文件内容

  • convert.base64-encode：把文件内容转换成base64编码

  • resource=secret.php：要读取的文件名是secret.php 。

data://text/plain;base64,PD9waHAgcGhwaW5mbygpOz8+（直接执行代码）

注：- data://：PHP的伪协议

  • text/plain：MIME类型（表示“纯文本”）。

  • base64,：表示后面的字符串是base64编码的。

  • PD9waHAgcGhwaW5mbygpOz8+：这是<?php phpinfo(); ?>的base64编码（phpinfo()是PHP的函数，会显示PHP的版本、配置、扩展等信息）。

防御措施： 用白名单代替黑名单（只允许包含特定目录的文件，如/var/www/html/）。

对输入严格过滤。

禁用allow_url_include（防止远程文件包含）。

对路径做严格验证（如realpath()获取绝对路径，检查是否在允许目录内）。

文件上传

本质：攻击者上传文件时，服务器未对文件做严格检测，导致“恶意文件被保存并执行”。

绕过检测的技巧：

1. 00截断：

旧版PHP（<5.3.4）处理字符串时，遇到%00（空字符）会停止，只取前面的部分，用这个漏洞通过%00截断路径（如ABC.php%00.jpg，服务器只取ABC.php,这样可以上传服务器原本禁止上传的文件，比如例子中带.php 后缀的文件）。

2. 双写后缀：

服务器解析文件后缀时，可能只看最后一个.php，或者中间的.jpg被忽略，此时你可以在.php后面加上 .jpg ，然后上传成功。

3. .htaccess解析：

.htaccess是Apache服务器的“配置文件”，可以设置“让.jpg文件当.php执行”，在.htaccess该文件中写下 AddType application/x-httpd-php .jpg 这个内容，让图片文件（如evil.jpg）以PHP执行，然后服务器就可以执行里面的代码。

利用流程： 绕过前端检测（如JS验证文件类型）。

绕过后端检测（如MIME类型、文件头、后缀黑名单）。

上传Webshell（如evil.php或evil.jpg，即恶意文件）。

访问Webshell（如http://site.com/uploads/evil.jpg 。

防御措施： 检测文件内容 生成随机文件名 禁用.htaccess

Webshell提权

本质：通过Webshell（恶意代码）获取服务器控制权，再提升权限（从普通用户升级到root）。

Webshell类型： PHP，ASP，JSP。
以上三种都属于“一句话木马”，因为代码简短。
攻击者使用专门的工具 填入木马文件的网址，填入密码，然后获取文件。

提权方式：

SUID提权：系统给一些程序特殊通行证，使得具有普通权限的用户可以修改密码，这个通行证叫 SUID ，攻击者可以寻找哪些程序开启了 SUID，但它本身又可以被操控，从而利用它来执行 root 命令。

内核漏洞：攻击者可利用Linux系统本身的漏洞，获取root权限。

服务漏洞：利用运行中的服务（如SSH、MySQL）的漏洞，提权到root。

持久化： 添加系统用户
安装后门

Base64编码的应用

本质：把恶意内容（如Webshell、命令）转换成“看不懂的字符串”，绕过过滤。

常见场景： 编码Webshell，编码命令， 绕过过滤： 过滤系统可能只检测“明文危险字符”（如cat、/），但不认识Base64编码的字符串，所以能通过检测。

学习日记1 网络安全基础

本篇涵盖网络安全基础概览、发展历史与法律法规，并重点讲解 Windows 操作系统在信安实战中的常用命令、进程排查及防火墙配置。

一、 网络安全简介

定义（不完全严谨版本）：

广义的网络安全即网络空间安全，网络空间由设施与网络组成。

狭义的是指采取必要措施防范外部对网络的各种攻击破坏，保障网络中的信息与数据。

发展历史：

通信安全时期 > 信息安全时期 > 信息保障时期 > 网络空间安全时期 

**1           2              3              4**

时期1仅限于保证信息的物理安全以及通过密码解决保密问题；

时期2主要确保信息的完整性、可用性、保密性；

时期3新增了可控性与不可否认性两个原则，且从业务，安全体系，管理三方面构建企业信息保障体系；

时期4扩大了信息安全的内涵与外延。

重大事件 \

📅 1988年：[Morris 蠕虫] 首个网络蠕虫，开启互联网安全纪元。

📅 1999年：[CIH 病毒] 首个破坏硬件BIOS的病毒。

📅 2000年：[爱虫病毒] 全球邮件风暴，损失巨大。

📅 2003年：[SQL Slammer] 极短时间内瘫痪全球网络。

--- (2000s 中后期 安全沉淀) ---

📅 2011年：[RSA SecurID] 安全令牌数据失窃。

📅 2013年：[棱镜门 PRISM] 全球隐私监听曝光 / [Target] 支付系统入侵。

📅 2014年：[Heartbleed] 互联网“心脏出血”漏洞。

📅 2017年：[WannaCry] 勒索病毒全球爆发 / [Equifax] 征信巨头泄露 / [NotPetya] 擦除器攻击。

📅 2020年：[SolarWinds] 供应链攻击曝光。

📅 2021年：[Colonial Pipeline] 关键基础设施勒索断供 / [Log4Shell] 十年来最严重漏洞。

📅 2024年：[XZ Utils] 开源软件供应链后门。

证书与赛事

证书：CISSP、CISA、CISP、CCSP、CCNA Security、网络工程师相关证书 赛事：CTF、XCTF、全国大学生网络安全竞赛、ISC2024、SCTF

网络安全意识与法律法规

<安全意识>

密码管理、社工防范、钓鱼邮件识别、移动办公安全、USB 安全 企业员工常见风险：弱口令、未经授权软件、外部链接点击

<主要法律法规>

《中华人民共和国网络安全法》《数据安全法》《个人信息保护法》 《关键信息基础设施安全保护条例》 等保2.0：信息安全等级保护制度

二、操作系统

操作系统简介： 管理计算机硬件与软件资源的程序。在网安视角下，OS 提供各种接口（端口、进程、服务），这些接口是受到攻击的切入点。

主要分为桌面级（Windows/macOS，易上手）和服务器级（Linux/Unix，稳定性高，绝大多数黑客攻击目标）。

Windows 系统 {

1. 常用命令（基础知识排查工具）

               可用 CMD 或 PowerShell 运行
              可用win+R打开运行窗口，输入cmd打开

基础导航与文件操作

dir：列出当前文件夹里的所有内容。

cd 目录名：进入指定文件夹。

md 新文件夹名：创建一个新的文件夹。

type 文件名.txt：直接在命令行里查看文本文件的内容。

copy 原文件 目标路径：复制文件。

move 原文件 目标路径：剪切（移动）文件。

del 文件名：删除文件。

电脑系统查询

ver：查当前 Windows 的版本号。

具体应用{ 根据版本号去查询是否存在已知的、针对该版本的公开漏洞 }

hostname：查这台电脑的名字。

具体应用{ 名称可能包含“DC”（域控制器）、“SQL ”（数据库服务器）等敏感信息，能帮助攻击者判断其 重要性 }

date / time：查看或修改当前系统的日期和时间。

具体应用{ 攻击者可能修改时间去干扰日志记录(时间戳伪造与反取证)
攻击者可利用时间调试攻击Kerberos 等认证协议(计时攻击 )
电脑收到入侵时,第一时间核查系统时间是否异常. }
⚠️ 注意：修改系统时间是高权限操作。

getmac：查看电脑网卡的物理地址（MAC 地址 ）。

具体应用{ 攻击者可以读取MAC地址进行标记,后续可以再次定位(设备指纹标记) 获取MAC 地址 是进行ARP欺骗的必备条件[ARP欺骗是内网经典攻击,具体介绍不在此叙述] 防护者可记录恶意设备的MAC地址进行防御处理. }

网络基础侦测

ping 网站或IP：测试网络通不通，看有没有延迟。

具体应用{ 假设拿到了一个内网机器的权限，可编写脚本扫描全部主机，看有哪些机器开机。

}

ping 8.8.8.8 -t：持续不断地去 Ping 目标。

具体应用{ 使用 ping 8.8.8.8 -t 持续发包，排除网卡或网线接触不良干扰，确认目标到底是不通，还是单纯屏蔽了ICMP协议（禁Ping）。 }

tracert 网站或IP：路由追踪。 即可以看发出去的数据包经过了哪几台路由器才找到目标的。

具体应用{ 通过对目标域名或IP执行路由追踪，判断目标是否经过CDN加速节点，跳过这些节点找到陌生的源站服务器，从而进行攻击。 排查路由节点中是否存在商业WAF防护（如阿里云盾、Cloudflare等 相当于防火墙），可绕过这些再进行攻击。 }

nslookup 网址：查域名的 IP 地址（DNS解析）。

具体应用{ 通过查询NS记录和尝试DNS域传送漏洞（如ls -d 目标域名.com），批量获取目标内网或隐藏的子域名。 结合字典盲测查询，发现如 admin.xxx.com 或 test.xxx.com 等防护薄弱的内部测试后台入口。 }

进阶检测命令

ipconfig /all：查看完整网络配置。判断当前是否在域内、有没有多网卡、DNS 服务器配置等。

netstat -ano：极高频使用。查看本机所有活动的 TCP/UDP 连接及对应的 PID。常用于查找后门连接、异常端口监听（如反向 Shell）。

nslookup：DNS 解析验证。常用于探测内网 DNS 服务器，或判断是否存在 DNS 劫持。

arp -a：查看 ARP 缓存表。内网渗透中，可用于探测存活主机或检测 ARP 欺骗攻击。

systeminfo：必用命令。获取操作系统版本、安装日期和已安装补丁列表（KB号）。知道补丁情况，就能快速判断这台机器可能对哪些漏洞（如 MS17-010）免疫。

whoami：查看当前用户身份。提权第一句，判断是普通用户还是 SYSTEM。

}

2. 用户与组管理

图形工具：运行 lusrmgr.msc，可以看到所有的“本地用户和组”。

安全核心：在 Windows 中，有两个极其重要的隐藏用户：Administrator（超级管理员，目标就是拿下它）和 Guest（默认停用的访客）。如果你去渗透测试，第一步就是看有没有把 Guest 账户激活并提权到管理员组的操作痕迹。

3. 进程与软件管理

图形工具：Ctrl+Shift+Esc 打开任务管理器。

网安陷阱：攻击者常常伪装成系统进程（如 svchost.exe）。你需要学习如何查看进程的具体路径（右键->打开文件所在位置）。如果一个 svchost.exe 在 C:\Windows\Temp 下面，那绝对是病毒。

4. Windows 防火墙

简单理解：它是一个“守门的保安”。

实操：你在打靶机或者做内网渗透时，发现 3389（RDP远程桌面）连不上，90% 是因为防火墙没开 3389 端口。你能用 wf.msc 或者命令行 netsh advfirewall firewall 去手动添加入站规则。

5. RDP 远程桌面

协议端口：默认是 3389。

网安要点：这是黑客在拿下 Windows 服务器后最常做的事——开启 RDP 服务，给自己创建一个隐藏的管理员账号，然后通过 3389 端口远程登录，像操作自己的电脑一样操作受害服务器。知道 RDP 也是防护的第一步，平时不用建议直接禁用 3389。

从零搭建个人博客：新手避坑全流程指南

本篇指南结合了真实的踩坑经历整理而成。从环境配置到上网部署，专门整理了新手最容易遇到的问题及解决方法，希望能帮你节省大量时间。

一、 准备工作

1.先注册一个GitHub.com 账号，可以弄一个学生福利认证，但比较难弄，可以多试几次，B站教程如下https://www.bilibili.com/video/BV1Q1XdBCEUM?t=318.6

2.下载Watt Toolkit，这是很常见的一个加速器，可加速github，用别的也可以，这个软件的安装很简单，直接搜索下载即可。

二、 下载三个软件

搭建一个独立博客并不难，你只需要本地写好代码，然后通过 Git 发送到 GitHub Pages 上即可。在这之前，我们需要准备三个基础软件：

  1. 安装 Node.js（务必选择 LTS 长期支持版本）：这是运行博客框架的核心。 注：安装Node.js需要一些复杂的环境配置，建议去B站上找一些安装教程，在此我贴一下个人推荐的教程https://www.bilibili.com/video/BV1sbjgzwEBX?t=562.2 （ps：这个教程可能稍微年代老一点，如果安装新版的有些东西可能对不上，有些问题评论区会有解答的）

一些问题的解决方法：出现"error"的可以以管理员身份运行命令提示符 "不是内部或外部命令，也不是可运行的程序或批处理文件":https://www.bilibili.com/video/BV1zk4y1x74C?t=51.6

  1. 安装 Git：用来把本地代码推送到网上。 注：git的安装没有那么复杂，具体流程就是去官网上找安装包，安装条件全部默认即可。

  2. 安装 VS Code：你将在这里写博客的源代码，并执行后面的命令行操作。

0x03 重点：XSS漏洞零基础核心知识 做完本题最大的收获：分清「前端变量篡改」和「真实XSS漏洞」。

1. 什么是XSS漏洞？

XSS（跨站脚本攻击，Cross-Site Scripting）是Web中最经典的高危漏洞之一。

漏洞成因：网站对用户输入的内容没有做过滤，转义，进化，导致攻击者可以提交恶意JS代码，代码被页面解析执行，从而实现劫持页面、窃取 Cookie、钓鱼、篡改页面等攻击行为。

简单来说：用户写的代码，被网站原样运行了，攻击者利用它让浏览器跑任意脚本。

2. XSS漏洞三大分类

####（1）反射型XSS（非持久化） 恶意代码通过URL 参数传递，一次性执行、不会存储在服务器，仅当前访问生效。

特点：需要诱导用户点击特制链接，时效性短、无法持久。

常见场景：搜索框回显、URL参数直接渲染页面。

经典测试Payload：`<script>alert(1)</script>`

####（2）存储型XSS（持久化） 用户提交的恶意JS代码，被服务器存入数据库、文件、留言板等，所有访问该页面的用户都会触发漏洞。

特点：危害最大、持久性强、无需诱导点击，属于高危漏洞。

常见场景：论坛留言、评论区、个人资料编辑、文章投稿。

####（3）DOM型XSS 不经过服务器数据交互，完全由前端JS逻辑导致的漏洞。前端JS直接读取URL、Location、Hash等参数，操作DOM节点渲染页面，未过滤参数导致代码执行。

特点：纯前端漏洞，流量不会经过服务器，隐蔽性极强。

3. XSS常见攻击危害

  • 窃取用户 Cookie，实现账号劫持、登录他人账号。
  • 篡改页面内容，搭建钓鱼页面、诱导用户输入信息。
  • 配合 CSRF 漏洞，执行越权操作。
  • 植入恶意代码、挖矿脚本、木马等。

4. XSS基础防御方案（开发&安全必知）

  • 输入过滤：严格过滤特殊字符 < > & " ' 等，阻止恶意代码注入。
  • 输出转义：前端渲染动态数据前，统一进行 HTML 实体转义，防止标签被解析。
  • Cookie HttpOnly：禁止 JS 读取 Cookie，防止会话劫持。
  • 开启 CSP 策略：限制页面恶意脚本执行。

0x04 前端安全延伸知识点

JS存取器 get/set

本题中 score 属于 JS 存取器属性，拥有 get（读取）和 set（赋值）方法。即便前端写死分数限制逻辑，用户依旧可以通过浏览器控制台强制赋值绕过。请牢记：所有前端校验都是不可信的。

安全开发铁律： 核心业务判断、权限校验、数据统计等逻辑，绝不可信任前端，必须放在后端实现。
