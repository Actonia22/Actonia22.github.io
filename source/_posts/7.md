##  案例分析  

### 📌 案例1：GET请求参数暴露导致的Flag泄露
**场景描述**：某CTF题目中，用户登录页面通过GET方法传递用户名参数，URL格式为 `login.php?username=admin`。
**漏洞分析**：
- GET请求将参数直接暴露在URL中，容易被浏览器缓存和历史记录
- 攻击者可以通过查看浏览器历史记录或直接查看URL获取敏感信息
**解决方案**：
```bash
# 使用view-source协议查看原始代码
view-source:http://靶机地址/login.php?username=admin
# 在源代码中搜索flag
Ctrl+F "flag"
```
**防御建议**：
- 敏感操作应使用POST方法
- 对GET参数进行加密处理
- 实现CSRF防护机制  

### 📌 案例2：Cookie伪造提升权限
**场景描述**：某网站只有admin用户才能查看flag，Cookie中包含 `role=guest`。
**漏洞分析**：
- Cookie未进行有效验证
- 可以直接修改Cookie值绕过权限检查
**攻击步骤**：
1. 使用开发者工具查看Cookie：`Cookie: role=guest; session=xxx`
2. 修改Cookie值为admin：`Cookie: role=admin; session=xxx`
3. 刷新页面获取flag
**防御建议**：
- 对Cookie进行签名验证
- 实现权限检查机制
- 使用HttpOnly标志保护Cookie  

### 📌 案例3：X-Forwarded-For IP伪造绕过限制
**场景描述**：某网站根据客户端IP进行访问限制，只允许内网IP访问。
**漏洞分析**：
- 服务器信任X-Forwarded-For头
- 可以伪造IP绕过访问限制
**攻击步骤**：
```http
# 构造恶意请求
GET /admin.php HTTP/1.1
Host: target.com
X-Forwarded-For: 127.0.0.1
```
**防御建议**：
- 验证X-Forwarded-For头的真实性
- 实现IP白名单机制
- 记录真实客户端IP  

### 📌 案例4：Content-Type导致的文件上传漏洞
**场景描述**：某网站允许用户上传图片文件，但未正确验证文件类型。
**漏洞分析**：
- 攻击者可以修改Content-Type绕过检测
- 可能导致远程代码执行
**攻击步骤**：
1. 准备恶意文件（如webshell.php）
2. 修改Content-Type为image/jpeg
3. 上传文件获取webshell
**防御建议**：
- 验证文件内容而非仅依赖Content-Type
- 实现文件类型白名单
- 对上传文件进行病毒扫描  

### 📌 案例5：HTTP请求走私攻击
**场景描述**：某网站同时支持CL（Content-Length）和TE（Transfer-Encoding）头。
**漏洞分析**：
- 攻击者可以利用CL和TE的不一致进行请求走私
- 可能导致缓存污染或权限提升
**攻击步骤**：
```http
POST / HTTP/1.1
Host: vulnerable.com
Content-Length: 100
Transfer-Encoding: chunked
0
GET /admin HTTP/1.1
Host: vulnerable.com
```
**防御建议**：
- 禁用Transfer-Encoding头
- 实现严格的请求验证
- 定期进行安全审计
