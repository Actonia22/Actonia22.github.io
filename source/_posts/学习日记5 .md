## 1. 查看源代码：发现隐藏的线索

在CTF比赛中，查看源代码是发现**隐藏信息**的重要手段。

### 🖱️ 常用方法与具体操作

| 方法 | 具体操作步骤 | 适用场景 |
| :--- | :--- | :--- |
| **鼠标右键** | 在网页空白处点击鼠标右键，选择“查看网页源代码”或“检查”。 | 寻找隐藏在HTML注释中的<mark>Flag</mark>（如 `<!-- flag{xxx} -->`）。 |
| **Ctrl + U** | 直接按下键盘上的 `Ctrl + U` 组合键，浏览器会立即新建一个标签页显示源代码。 | 某些网站使用 JS 屏蔽了右键菜单，使用这个方法可**完美绕过**。 |
| **开发者工具(F12)** | 按 `F12` 键，切换到 `Elements` 标签页。 | 查看经过JS动态渲染后的**最终DOM结构**，而不是**原始文件**。 |
| **view-source协议** | 在浏览器地址栏，将 URL 前面手动加上 `view-source:` 并回车。 | 前两个方法行不通，突破**前端限制**，获取服务器返回的**原始形态代码**（常用作绕过前端JS加密/跳转）。 |
  
### 🖱️  通俗解释  

“原始文件” 是由服务器发送的**静态**文本字符串，无论你在网页上进行了什么操作，这堆原始字符都不会变。  
  
“最终 DOM 结构” 是由HTML 解析器 **动态** 解析原始文件生成了一棵DOM树，随后，浏览器会立刻执行文本里包含的 JavaScript 代码。
  
“view-source” 是浏览器内置的一个“伪协议”，在URL 前面手动加上 `view-source:` 可以发送 HTTP GET 请求和强制进入“原始文本显示模式” 。  
>view-source:协议 完全不启动 JS 引擎。  
  
“前端限制” ：反爬/反调试脚本，右键屏蔽等前端逻辑限制你的操作。

### 💡 操作示例

- **突破前端限制**：如果网页用 JS 屏蔽了右键，直接在地址栏输入 `view-source:http://靶机地址/login.php` 即可获取原始代码。  

- **寻找隐藏线索**：如果你先按 Ctrl+U 看原始源码，如果发现 什么都找不到，使用 `Ctrl + F` 在源代码页面搜索 `flag`、`key`、`password` 或 `admin` 等关键词，通常能快速定位到题目答案。

```html
<!-- 实战案例：在地址栏输入以下格式，获取未经渲染的源码 -->
view-source:http://www.qingcen.net/login.php
```

## 2. 开发者工具：你的解题利器

开发者工具（F12）是CTF解题的“瑞士军刀”。

### 📊 核心面板与实战操作

#### 🔹 Elements（元素/检查器）     - **修改前端限制**
  
- 查看实时DOM
- 实时编辑HTML和CSS
- 查看盒模型和计算样式

注：<abbr title="在 CSS 布局引擎中，每一个 HTML 元素在浏览器渲染时，都会被描绘成一个由内容区、内边距、边框、外边距构成的矩形区域">盒模型</abbr>在 F12 中的 Elements 面板右侧，“Computed” 标签页中的特定区块；点击这个区块上图形的数字，可以修改当前元素的边距大小，浏览器会**实时重绘**页面的布局。  
  
计算样式：<p>
浏览器在渲染页面时，会收集元素上所有的
<span title="通过 &lt;link rel=&quot;stylesheet&quot;&gt; 引入的独立 .css 文件，多用于全局样式复用">外部 CSS 文件</span>（包括
<span title="直接写在 HTML &lt;head&gt; 中的 &lt;style&gt;...&lt;/style&gt; 代码块，作用于当前页面">嵌入式 &lt;style&gt; 标签</span>、
<span title="直接写在 HTML 元素标签内部的 style=&quot;...&quot; 属性，拥有最高的单条优先级">内联 style="" 属性</span>，以及
<span title="子元素默认继承父元素的部分样式属性，如字体颜色 font-color、行高 line-height 等">CSS 继承的样式</span>）。经过 CSS 的
<abbr title="浏览器按照 !important、ID、类、标签等权重规则，计算多份样式冲突时最终谁胜出的算法">层叠（Cascade）与优先级计算</abbr>后，最终确定的、实际生效的样式，就被称为
<span title="浏览器对 CSS 进行 2D/3D 计算后的实际像素值，例如开发者写了 width: 50%，这里会显示计算出的真实像素值如 640px">“计算样式”</span>。
</p>

- **操作步骤**：按 `F12` -> 点击左上角的小箭头（或按 `Ctrl+Shift+C`） -> 点击页面上想要修改的输入框或按钮。  

- **实战操作**：如果页面提示“只能输入3位验证码”，在 `Elements` 面板中找到 `<input maxlength="3">`，**双击**将 `3` 改成 `99`，返回页面即可输入超长字符串进行测试；或者发现按钮是 `disabled`（禁用状态），直接把 `disabled` 属性**删除**，按钮就能立即点击。  
}

#### 🔹 Console（控制台） - **执行JS代码**  
  
- 执行JavaScript代码（主要）
- 查看日志、错误、警告
- 查看网络请求、安全错误等

> **JSFuck详解**：<mark>JSFuck</mark>是一种基于JavaScript的深奥编程风格，只用6个字符就能编写出任何有效的JavaScript代码：`[]()!+`。<p>JSFuck 的核心原理，正是利用了 JavaScript 的
<span title="将变量的数据类型从一种（如数字）强制改变为另一种（如字符串）的过程，JSFuck 中经常利用 + 号来触发此行为">类型转换</span>、 <span title="由 JS 引擎在运算或比较时自动执行、无需开发者显式调用 String()/Number() 等函数的数据类型改变">隐式转换</span> 和 <span title="JS 中数组、字符串本质上都是对象，通过 . 或 [] 操作符可以提取特定属性或原型方法，这在 JSFuck 中是获取字符和构造函数的基础">对象属性访问特性</span>。</p> 解码方式是将编码得到的JSFuck表示放在控制台并回车。

- **操作步骤**：按 `F12` -> 点击 `Console` 标签页 -> 在 `>` 提示符后输入 JS 代码并回车。  

- **实战操作**：  

  - 输入 `document.cookie` 并回车，直接查看当前页面存储的浏览器 <mark>Cookie</mark> 信息。  

  - 输入 `alert(1)` 测试是否存在 XSS 漏洞。  

  - 输入 `function test(){console.log("成功")}; test();` 自定义函数调试。

- **JSFuck解码实战**：遇到题目给出一串类似 `[][(![]+[])...]` 的代码，直接**复制粘贴**到 Console 控制台中并按下回车，即可立即解码出原本的 JS 逻辑。  
      

#### 🔹 Network（网络面板） - **分析请求过程**  
  
- 请求列表：每列可自定义（Name、Status、Type、Initiator等）  
- 请求按**时间**顺序排列  
- 颜色标识：绿色（缓存或304）、蓝色（正常加载）、红色（失败请求）

#### 请求详情

- Headers：请求和响应头
- Preview：响应预览（JSON、图片等）
- Response：原始响应数据
- Timing：详细的请求时间线
- Initiator：触发请求的调用栈

---

- **操作步骤**：按 `F12` -> 点击 `Network` 标签 -> 勾选左上角的 **`Preserve log`（保留日志）** -> **刷新网页**。此时页面发出的所有请求都会出现。  

- **实战操作**：  

  - 点击某个 `.php` 或 `.js` 请求，点击右侧的 **`Headers`**：查看 `Cookie`、`User-Agent` 等发送给服务器的信息。  

  - 点击 **`Response`**：查看服务器返回的原始数据。如果是 JSON 格式的接口，可能直接包含账号密码或 <mark>Flag</mark>。  

  - **技巧**：观察请求列表的“大小（Size）”和“耗时（Time）”，快速找出被隐藏的后台 API 接口。
  
#### 🔹 Application（应用面板） - **伪造身份**
  
- 管理浏览器本地存储资源，包括Cookies、<mark>LocalStorage</mark>等  
- Cookie管理：查看、编辑、删除Cookie，设置Domain、Path、Expires等  
- 一般会在“应用”里的“存储”部分查看cookie相关信息，也是CTF中收集信息的重要位置  

- **操作步骤**：按 `F12` -> 点击 `Application` 标签 -> 点击左侧 `Storage` 下的 `Cookies` -> 查看 `https://当前域名` 下的列表。  

- **实战操作**：  

  - 当题目要求“必须是 admin 才能查看 flag”时，**双击** Cookie 列表里的 `role` 或 `user_id` 值，将其手动修改为 `admin` 或 `1`。  

  - 点击下方**灰色**区域可添加新 Cookie（如添加 `flag=1` 绕过服务器逻辑），修改后**刷新页面**，看是否触发漏洞。
