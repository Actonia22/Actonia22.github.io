# CTF入门 | 简单的XSS 漏洞解题

> 本次文章结合实战靶场题目，复盘解题思路，同时讲解XSS漏洞核心基础知识，适合Web安全新手入门学习。

## 0x00 前言
本次协会周练遇到一道名为“简单的XSS”的Web入门题目，靶场是第一人称射击小游戏。最初被URL内的XSS载荷误导，陷入传统反射型XSS的解题思维，踩坑后复盘完整解题流程。

靶场地址：[http://62.234.23.150:8080/](http://62.234.23.150:8080/)

题目描述：丧尸病毒入侵这个世界，你需要打倒1000只丧尸获取flag。

## 0x01 页面初步观察
打开链接进入游戏首页，核心规则：击杀丧尸累计1000分即可获取flag。

游戏操作按键：
* WASD：人物移动
* 鼠标：瞄准目标
* 鼠标左键：连发射击
* R：换弹
* ESC：暂停游戏

浏览器地址栏自带一段<abbr title="载荷是指攻击者或测试者发送给目标系统的一段数据/代码，XSS测试载荷就是专门用来探测网页是否有跨站脚本漏洞的“探针代码”。">XSS测试载荷</abbr>：
```html
?name=<img%20src=x%20onerror=alert(1)>
```

>💡 踩坑提醒： 该载荷是纯粹的题目干扰项！本题不存在任何XSS漏洞，只是题目名称和URL参数刻意误导。

手动刷满1000分耗时极长，由此判断：分数、领奖逻辑全部由前端JS控制，无后端校验，可直接控制台篡改数据通关。

## 0x02 实战解题步骤

### 1. 打开调试工具
页面按下 `` `F12` `` 打开开发者工具，切换至 `` `Console` `` 控制台。

### 2. 分析核心JS对象
页面存在全局 `` `game` `` 对象，包含所有核心业务逻辑：
*   `` `game.score` ``：存取器属性，存储当前游戏分数
*   `` `game.claimReward()` ``：异步领奖函数，分数达标即可弹出flag
*   `` `game.start()` ``：游戏启动函数

### 3. 核心代码执行（一键通关）
直接在控制台修改分数为1000，调用领奖函数：

```javascript
// 篡改前端分数，绕过游戏击杀校验
game.score = 1000;

// 调用官方领奖接口，获取Flag
game.claimReward();
```

代码执行后，页面直接弹窗输出flag，题目通关。

0x03 重点：XSS漏洞零基础核心知识
做完本题最大的收获：分清「前端变量篡改」和「真实XSS漏洞」。

### 1. 什么是XSS漏洞？
**XSS**（跨站脚本攻击，Cross-Site Scripting）是Web中最经典的高危漏洞之一。

漏洞成因：网站对用户输入的内容**没有做<abbr title="拒绝或移除非法字段；把可能被解释为代码的特殊字符替换为安全的文本实体；对允许部分 HTML 的输入进行“消毒”，保留安全的标签，规范化危险内容。">过滤，转义，进化</abbr>**，导致攻击者可以提交恶意JS代码，代码被页面解析执行，从而实现<abbr title="攻击者让受害者打开的网页行为被接管（插入或运行攻击脚本），使页面按照攻击者意图展示或执行操作。">劫持页面</abbr>、<abbr title="Cookie 是浏览器为某个网站保存的小片段数据，窃取Cookie是指通过脚本读取浏览器存储的 Cookie（若未设置 HttpOnly），拿到会话凭证后冒充用户登录/访问受保护资源。">窃取 Cookie</abbr>、<abbr title="在真实页面内注入或跳转到伪造界面，欺骗用户输入敏感信息（账号、密码、验证码等）。">钓鱼</abbr>、<abbr title="顾名思义，修改页面内容从而误导用户/伪装重要信息">篡改页面</abbr>等攻击行为。

简单来说：**用户写的代码，被网站原样运行了，攻击者利用它让浏览器跑任意脚本。**

### 2. XSS漏洞三大分类
####（1）反射型XSS（非持久化）
恶意代码通过<abbr title="将数据放在网址里传给服务器或页面 常见形式：问号+查询字符串 例子:?name=alice&age=20 表示传递了两个参数 name=alice 和 age=20。">URL 参数传递</abbr>，一次性执行、不会存储在服务器，仅当前访问生效。

特点：需要诱导用户点击特制链接，时效性短、无法持久。

常见场景：搜索框回显、URL参数直接渲染页面。

经典测试Payload：`` `<script>alert(1)</script>` ``

####（2）存储型XSS（持久化）
用户提交的恶意JS代码，**被服务器存入数据库、文件、留言板等**，所有访问该页面的用户都会触发漏洞。

特点：危害最大、持久性强、无需诱导点击，属于高危漏洞。

常见场景：论坛留言、评论区、个人资料编辑、文章投稿。

####（3）<abbr title="文档对象模型，浏览器用来表示和操作网页内容的树形结构">DOM</abbr>型XSS
不经过服务器数据交互，**完全由前端JS逻辑导致的漏洞**。前端JS直接读取URL、Location、Hash等参数，操作DOM节点渲染页面，未过滤参数导致代码执行。

特点：纯前端漏洞，流量不会经过服务器，隐蔽性极强。

### 3. 本题为什么不是XSS漏洞？
*   题目URL中的Payload只是文本参数，**页面并未解析、执行这段JS代码**
*   全程没有用户输入渲染、没有代码解析执行的过程

通关方式只是单纯的前端 JS 变量篡改，属于典型的前端校验绕过，与 XSS 代码注入完全无关。

**总结：** 本题实则是披着 XSS 外衣的「前端安全基础题」，非常适合用来帮助新手区分“伪漏洞”和“真实漏洞”。

### 4. XSS常见攻击危害
*   窃取用户 `Cookie`，实现账号劫持、登录他人账号。
*   篡改页面内容，搭建钓鱼页面、诱导用户输入信息。
*   配合 CSRF 漏洞，执行越权操作。
*   植入恶意代码、挖矿脚本、木马等。

### 5. XSS基础防御方案（开发&安全必知）
*   **输入过滤**：严格过滤特殊字符 `< > & " '` 等，阻止恶意代码注入。
*   **输出转义**：前端渲染动态数据前，统一进行 HTML 实体转义，防止标签被解析。
*   **`Cookie HttpOnly`**：禁止 JS 读取 Cookie，防止会话劫持。
*   **开启 CSP 策略**：限制页面恶意脚本执行。

## 0x04 前端安全延伸知识点
**JS存取器 get/set**

本题中 `score` 属于 JS 存取器属性，拥有 `get`（读取）和 `set`（赋值）方法。即便前端写死分数限制逻辑，用户依旧可以通过浏览器控制台强制赋值绕过。**请牢记：所有前端校验都是不可信的。**

**安全开发铁律：** 核心业务判断、权限校验、数据统计等逻辑，**绝不可信任前端，必须放在后端实现。**
